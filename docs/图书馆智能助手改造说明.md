### 功能一览（当前演示行为）

| 能力 | 说明 |
|------|------|
| 借书 | 表单收集书名、索书号；确认后由 SQLite 判定在架并更新借阅状态 |
| 还书 | 同上；对已借出记录办理归还 |
| 空间预约 | 收集空间类型与时段；**演示规则**判定成功与否（未接预约系统） |
| 借阅指引 / 数据咨询 | 固定话术；数据类不编造统计数字 |
| 推荐阅读 | 按主题槽位查询 SQLite 在架书名（演示，非馆藏承诺） |
| FAQ | 检索意图 `faq/*`（开闭馆、借阅规则、静音区、Wi‑Fi、占座规则等） |

自定义动作见 `backend/actions/actions.py`。接入 OPAC、预约系统或报表 API 时需替换为真实调用。

## 二、对话与数据层（Rasa）需修改的文件

本节描述 **Rasa 工程根目录 `backend/`** 下与对话、NLU、策略相关的文件：职责、当前状态与**可继续优化**的方向。路径均相对于 `backend/`。

### 2.0 文件总览（按数据流）

| 路径 | 职责 | 状态 |
|------|------|------|
| `domain.yml` | 意图、实体、槽位、表单、`responses` 内联回复、`session_config`、注册 actions | ✅ |
| `data/nlu.yml` | 意图例句与实体标注，供 DIET / 检索意图训练 | ⏳ |
| `data/rules.yml` | 单轮规则（问候、能力、FAQ、激活表单等） | ✅ |
| `data/stories.yml` | 多轮故事（表单提交、确认、否认分支） | ✅ |
| `data/responses.yml` | 检索意图 `faq/*` 的 `utter_faq/...` 与片段 | ✅ |
| `data/cites.yml` | `floor_zone` 等 **lookup** 表，辅助实体边界 | ⏳ |
| `data/dict.txt` | **Jieba** 用户词典，与 `config.yml` 中 `JiebaTokenizer` 引用一致 | ⏳ |
| `config.yml` | NLU Pipeline（分词、DIET、ResponseSelector、Fallback 等）与 Policy | ⏳ |
| `tests/test_stories.yml` | `rasa test` 对话回归 | ⏳ |
| `endpoints.yml` | Action、Tracker 等**服务端点**（严格属部署层，常与对话联调一起看） | ✅ |

### 2.1 `domain.yml` — ✅

| 要点 | 说明 |
|------|------|
| 意图 / 实体 / 槽位 / 表单 | 馆场景已替换医院域；含 `nlu_fallback`、检索 `faq` |
| 表单 `ignored_intents` | 避免与其它业务规则叠答（见操作指引 FAQ §6） |
| `session_config` | 建议非 0 过期时间 + 按需关闭跨会话槽位继承，减轻「死循环追问」 |
| 下一步 | 新增能力时同步 `actions` 列表与 `responses`，并跑 `rasa train` |

### 2.2 `data/nlu.yml` — ⏳

| 优化方向 | 说明 |
|----------|------|
| 口语与拼写变体 | 问候、能力询问等增加拼音/简称（如 `nihao`、`功能`），减少误落入 `nlu_fallback` |
| 实体覆盖 | `book_title`、`call_number`、`room_type`、`time_slot`、`topic` 多举馆编目常见写法 |
| 易混意图 | 「借书流程」偏 `borrow_guide`，「我要借书」偏 `borrow_book`；边界例单独标注 |
| 负例 / 兜底 | 可少量增加 `out_of_scope` 或与 `FallbackClassifier` 阈值联调（不必堆叠海量负例） |

### 2.3 `data/stories.yml` 与 `data/rules.yml` — ✅

| 优化方向 | 说明 |
|----------|------|
| `rules.yml` | 保持「短平快」单轮；复杂分支放 `stories.yml`，避免与 RulePolicy 抢预测 |
| `stories.yml` | 补充「表单中否认」「连续两次否认」「借还成功后追问 FAQ」等 happy / unhappy 混合路径 |
| 与表单一致性 | 故事中的 `intent` / `active_loop` 名称须与 `domain.yml` 中表单名一致 |

### 2.4 `data/responses.yml` — ✅

| 优化方向 | 说明 |
|----------|------|
| FAQ 粒度 | 预约、罚款、存包等若增多，可拆更多 `utter_faq/...` 子意图并在 `nlu.yml` 对齐 |
| 话术长度 | 检索回复宜分段或列表，便于前端展示与无障碍 |

### 2.5 `data/cites.yml`、`data/dict.txt` 与 `config.yml`（NLU 侧）— ⏳

| 文件 | 优化方向 |
|------|----------|
| `cites.yml` | 为阅览室名、校区、馆藏地等增加 lookup，与 `nlu` 中实体例句同步 |
| `dict.txt` | 馆专用名、索书号模式中的高频词、系统名（OPAC、SIP2 等）固定词性，减少切分错误 |
| `config.yml` | 小语料时可略降 `DIETClassifier` / `ResponseSelector` 的 `epochs` 加快迭代；启用 BERT 前确认路径与算力；`FallbackClassifier.threshold` 与真实误触发率联调 |

### 2.6 `tests/test_stories.yml` — ⏳

| 优化方向 | 说明 |
|----------|------|
| 覆盖规则意图 | 已含 `greet`（含拼音问候）、`ask_capabilities`、`nlu_fallback`、`faq`（`utter_faq`）、`reading_recommend` 等短故事；可按需再拆 `faq/*` 子路径 |
| 覆盖表单入口 | 已含三表单**首步**（激活 `*_form`）；完整填槽—确认—API 结果仍建议逐步加长 |
| 维护成本 | 故事宜短；长流程用注释标明依赖的 Action / 槽位。Windows 上 `rasa test` 若遇模型解压错误，可换 Linux/WSL 或仅作 `rasa data validate` 校验 |

## 五、产品与合规（非代码但必须完善）

| 项 | 状态 | 说明 |
|------|------|------|
| 话术免责声明（演示非馆藏承诺） | ✅ | 见下文及 `domain` 中相关 utter |
| 身份与隐私、登录与会话策略 | ⬜ | PRD / 法务 |
| 无障碍与多语言 | ⬜ | 视服务对象 |
| 监控与告警（意图、表单放弃率、API 失败） | ⬜ | 运维 |

1. **身份与隐私**：借还、预约通常需读者身份；对话中是否登录、是否仅绑定会话 ID，需在 PRD 中定义，并符合个人信息保护要求。
2. **免责声明**：推荐与「数据解读」不构成专业建议。**演示话术**：推荐与数据类回复仅为演示，不构成馆藏或统计承诺；其中 DeepSeek 仅用于数据咨询文案生成，借还与推荐主流程仍以规则与业务数据为准。生产环境须对接真实业务系统、权限与审计，并采用馆方用户须知与免责声明。
3. **无障碍与多语言**：视服务对象增加简易模式或英文槽位说明。
4. **监控**：对意图分布、表单放弃率、API 失败率做日志与告警。
