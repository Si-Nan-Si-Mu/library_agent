# 本地开发与联调操作指引

> **文档索引**（所有 Markdown 说明入口）：[README.md](README.md)

本文档汇总在 **Windows + PowerShell** 下从零跑通 **Rasa 后端** 与 **Vue 前端** 的推荐命令与顺序。项目 Rasa 配置与数据在 `backend` 目录。

## 一、环境与目录约定


| 项                  | 说明                                                  |
| ------------------ | --------------------------------------------------- |
| Python             | 建议使用 **Python 3.10**（与 Rasa 3.6 匹配），示例环境名 `rasa310` |
| Conda              | 使用 Miniconda / Anaconda                             |
| 后端工作目录             | `D:\Python\library_agent\backend`（请按你本机仓库路径修改）      |
| 前端工作目录             | `D:\Python\library_agent\front\lib_agent_vue`       |
| Rasa API           | `http://127.0.0.1:5005`                             |
| Action Server      | `http://127.0.0.1:5055`                             |
| REST Webhook（前端填写） | `http://127.0.0.1:5005/webhooks/rest/webhook`       |

## 二、首次准备 Conda 环境（只需做一次）

在 **PowerShell** 中执行：

```powershell
conda create -n rasa310 python=3.10 -y
conda activate rasa310
python -m pip install -U pip setuptools wheel
pip install "rasa==3.6.21" "rasa-sdk==3.6.2" jieba flask requests neo4j
```

若 `conda activate` 在 PowerShell 中无效，先执行 `conda init powershell`，**关闭并重新打开**终端后再 `conda activate rasa310`。

验证：

```powershell
python -V
rasa --version
```

## 三、日常联调推荐顺序（三个终端）

表单（借书、还书、空间预约）与自定义 Action 依赖 **Action Server**，`backend/endpoints.yml` 已指向 `http://127.0.0.1:5055/webhook`。必须先起 **5055**，再起 **5005**。

### 终端 1：Action Server（保持运行，不要关）

```powershell
conda activate rasa310
cd D:\Python\library_agent\backend
.\start_actions.ps1
```

看到 `Action endpoint is up and running on http://0.0.0.0:5055` 即正常。

**书目演示库（Neo4j）**：首次触发馆藏相关 Action 时，会在 Neo4j 中创建 `:LibraryBook` 唯一约束（`book_key`）并在**空库**时写入少量经典种子。每条馆藏为**单一节点**：`lib_book`（题名）、`summary`（简介）、`book_pos`（架位）、`is_borrow`（借阅标记）均为该节点属性，**不再**使用架位子图节点。默认**不会**再把目录自动「撑到 120 条」无图谱边的 SEED 副本（避免出现大量孤立黄点）；若仍需要旧版大目录演示，可在 `.env` 中设置 `**LIB_AGENT_MIN_CATALOG=120`**。运行 `**python kg_module\import_data.py**` 导入 CSV 后，会自动**删除**无任何 `WRITTEN_BY→Author` 的孤立 `:LibraryBook`** 及无对应副本的 `:BorrowRecord`**。务必先启动 Neo4j 并在 `.env` 中配置 `NEO4J_*`（见下文 Docker 小节）。借书：表单先只采集书名，系统列出在架可借副本及架位；仅一条时自动带出索书号并进入确认；多条时可回复索书号或序号。还书：先书名，仅列出已借出副本；多条时同上。借阅流水在 `:BorrowRecord`。可在 `backend` 目录下执行 `python scripts/seed_library_graph.py`（或在**仓库根目录**下执行 `python backend/scripts/seed_library_graph.py`）预先灌库；须已配置环境变量。

**推荐阅读衔接借书（新增）**：推荐结果返回后，支持继续说 `借这本`、`那就借这本`、`借第2本`、`借第二本`，系统会自动回填推荐候选对应书名并进入借书确认流程。

**推荐阅读展示（结构化）**：后端 `action_reading_recommend` 通过 `json_message` 下发 `payload_type: reading_recommend`（在架 / 已借出 / 图谱书目分表）；前端以表格渲染。图谱扩展与馆藏共用 `**:LibraryBook`**（`book_key` 唯一），由 `backend/kg_module/raw_data/books.csv` 写入 `lib_book`/`title`、`rating`、`summary`，**可选列** `book_pos`（架位）、`is_borrow`（0 在架 / 1 已借出，亦支持「在架」「已借」等写法）有值时一并写入，及与 `:Author`/`:Category`/`:Topic`/`:Discipline` 的 `WRITTEN_BY`、`BELONGS_TO`、`COVERS_TOPIC`、`IN_DISCIPLINE` 关系；CSV 导入结束后会自动执行 `graph_networks.build_knowledge_networks()`（`author_relations.csv` 作者关系 + 作者—学科 `WORKS_IN` + 主题—学科 `UNDER_DISCIPLINE` + 同学科 `CONTEMPORARY_WITH`）。**仅清空作者/类目/主题/学科与遗留 :Book、保留馆藏节点与借阅流水后重导 CSV** 时，可执行 `python kg_module\import_data.py --reset --graph-only`。**连同馆藏与借阅流水一并清空、再导入 CSV 并重灌演示馆藏** 时，使用 `python kg_module\import_data.py --reset`（脚本末尾会调用 `ensure_bootstrap`；见下文「七、Docker」代码块）。修改 `backend/actions/actions.py` 或 `neo4j_library_store.py` 后须**重启 Action**；未配置 Neo4j 时借还与推荐阅读将无法返回馆藏数据。

### 测试 Neo4j 是否连通（本机）

以下在 **PowerShell** 中执行；Bolt 默认端口 **7687**，若 Desktop / Docker 改过端口，请替换命令中的端口号。

1. **端口是否在监听**（`TcpTestSucceeded : True` 仅表示本机该端口有服务，不等于账号密码一定正确）：

```powershell
Test-NetConnection -ComputerName 127.0.0.1 -Port 7687
```

1. **查看占用该端口的进程（可选）**：

```powershell
netstat -ano | findstr :7687
```

1. **用 Python + 官方驱动验证连接与认证**（需已 `pip install neo4j`，且仓库根目录或 `backend` 下已配置 `.env`；**勿**在公开渠道泄露密码）：

```powershell
conda activate rasa310
cd D:\Python\library_agent\backend
python -c "from kg_module.env_bootstrap import load_repo_dotenv; load_repo_dotenv(); from kg_module.neo4j_auth import resolve_auth, driver_kwargs; from neo4j import GraphDatabase; import os; uri=(os.environ.get('NEO4J_URI') or 'bolt://localhost:7687').strip(); d=GraphDatabase.driver(uri, auth=resolve_auth(), **driver_kwargs()); s=d.session(); print('RETURN 1 =>', s.run('RETURN 1 AS ok').single()['ok']); s.close(); d.close(); print('Neo4j 连接与认证正常。')"
```

若出现 `Unauthorized` / `AuthError`，请核对 `.env` 中 `NEO4J_USER`、`NEO4J_PASSWORD` 与实例是否一致；本地无鉴权测试需 `NEO4J_AUTH_NONE=1` 且 Neo4j 已关闭鉴权。

1. **Neo4j Browser / Cypher**（Desktop 点 **Open**，或浏览器访问 `http://127.0.0.1:7474`），登录后在查询框执行：

```cypher
RETURN 1 AS ok;
MATCH (lb:LibraryBook) RETURN count(lb) AS library_books;
MATCH (lb:LibraryBook)-[:COVERS_TOPIC]->() RETURN count(DISTINCT lb) AS graph_linked_books;
```

若 `library_books` 为 0，在 `backend` 下执行 `python scripts\seed_library_graph.py` 后**重启 Action**。

等价手动命令：

```powershell
conda activate rasa310
cd D:\Python\library_agent\backend
rasa run actions --port 5055
```

### 终端 2：Rasa API（保持运行）

```powershell
conda activate rasa310
cd D:\Python\library_agent\backend
.\start_rasa.ps1 -RunOnly -Port 5005
```

首次或改配置后需要先训练再启动时，可二选一：

```powershell

.\start_rasa.ps1 -TrainOnly -Clean

# 训练并紧接着启动 API（清理临时目录与旧模型包）
.\start_rasa.ps1 -Clean
```

**Windows 加载模型若出现 WinError 123**：脚本已通过 `python rasa_windows.py run` 启动 API，请勿在问题未解决时改回裸 `rasa run`。

等价手动启动 API（仍建议优先用脚本，以统一 `TEMP` 等）：

```powershell
conda activate rasa310
cd D:\Python\library_agent\backend
python .\rasa_windows.py run --enable-api --cors "*" --port 5005
```

自检：浏览器访问 `http://127.0.0.1:5005/status` 应返回 JSON。

### 终端 3：Vue 前端

```powershell
cd D:\Python\library_agent\front\lib_agent_vue
npm install
npm run dev
```

按终端提示用浏览器打开（默认 `http://localhost:8080`，见 `vite.config.js`）。

页面中 **Webhook** 填：

## 四、常见问题

### 1. `远程计算机拒绝网络连接` / `Cannot connect to host 127.0.0.1:5055`

**原因**：未启动 Action Server，或已关闭终端 1。  
**处理**：先按「终端 1」启动 `.\start_actions.ps1`，再重试对话。

### 2. `Failed to execute custom action ... no endpoint is configured`

**原因**：`backend/endpoints.yml` 中未配置 `action_endpoint`。  
**处理**：仓库已默认启用；若你改回注释，请取消注释并指向 `http://127.0.0.1:5055/webhook`。

### 3. 前端 `ERR_CONNECTION_REFUSED` 访问 5005

**原因**：终端 2 未启动或端口被占用。  
**处理**：确认 `.\start_rasa.ps1 -RunOnly` 或等价命令在运行。

### 4. 机器人返回空列表 `[]`

**原因**：常见为未加载模型、未重新训练、或用户说法无对应意图/规则。  
**处理**：在 `backend` 执行 `rasa train` 后重启 API；前端打开控制台查看 `[Rasa]` 中「响应体（原始字符串）」。

### 5. `pip` 仍是 Python 3.13

**原因**：未进入 `rasa310` 环境。  
**处理**：`conda activate rasa310` 后再执行 `pip -V` 确认路径含 `envs\rasa310`。

### 6. 每条正常回复后都多出一句「请问预约哪种空间…」

**原因**：曾进入过空间预约表单且会话未过期时，`space_booking_form` 仍在 `active_loop` 中；Rasa 在一次响应里会返回**多条** bot 消息（例如先 `utter_greet` 再追问槽位），前端按数组逐条展示，看起来像「重复」。  
**处理**：仓库已在 `domain.yml` 为表单配置 `ignored_intents` 并调整 `session_expiration_time`；在 `**rules.yml`** 中于问候、能力说明、FAQ、兜底等规则前增加 `**action_deactivate_loop**`，强制结束残留表单。更新后请 `**rasa train` 并重启 API**。若仍异常，删除 Local Storage 中的 `rasa_sender_id` 后刷新页面。

### 7. 只说「预约」却进入兜底话术

**原因**：单字/过短说法置信度不足，被 `**FallbackClassifier`** 判为 `nlu_fallback`。  
**处理**：`nlu.yml` 的 `space_booking` 意图已补充「预约」「我要预约」等例句；合并后务必 `**rasa train`**。仍误判时可略调 `config.yml` 中 `FallbackClassifier` 的 `threshold`（谨慎，易增加误触发）。

### 8. 日志里 `action_deactivate_loop` 404 / Action Server 找不到该动作

**原因**：`action_deactivate_loop` 是 **Rasa 内置动作**，由 Core 执行。若把它写进 `domain.yml` 的 `**actions:`** 列表，会被当成自定义动作发到 **5055**，Action Server 未实现即报 404。  
**处理**：从 `actions:` 中删除 `action_deactivate_loop`；`rules.yml` / `stories.yml` 里仍可照常写该动作名。改完后 `**rasa train`** 并重启 API。

### 9. 借书/还书表单问索书号时，只输入数字却变成「我不太明白」

**原因**：纯数字易被 `**FallbackClassifier`** 标成 `nlu_fallback`；若表单 `ignored_intents` 含 `nlu_fallback`，会**退出表单**并走兜底。  
**处理**：`domain.yml` 已去掉借/还/空间表单中的 `nlu_fallback` 忽略项，并为 `book_title`、`call_number` 增加 `**from_text`**（仅在对应 `active_loop` 且 `requested_slot` 匹配时把整句写入槽位）；`actions.py` 已支持把数字序号（如 `1`、`第2本`）解析为当前列表条目。更新后 `**rasa train**` 并重启 API 与 Action。

### 10. 预约流程里已问「哪种空间」，回复「研讨室」却变成兜底

**原因**：① 短句未标成 `room_type` 实体时易被标成 `nlu_fallback`；② 原兜底规则在**有活跃表单**时也会执行，`action_deactivate_loop` 打断预约。  
**处理**：`rules.yml` 中 `nlu_fallback` 仅在 `**active_loop: null`** 时触发；`data/cites.yml` 增加 `room_type` lookup；`ValidateSpaceBookingForm` 从**整句原文**归一化「研讨室→研讨间」等。更新后 `**rasa train`** 并重启 Action + API。

### 11. 借书时输入「红楼梦」或「我要借红楼梦」却触发兜底

**原因**：可能同时存在两类问题：① NLU 置信度不足被判为 `nlu_fallback`；② 仅启动了 Rasa API，未启动 Action Server，导致表单校验/提交无法正常执行。  
**处理**：先确认 `5055` 的 Action Server 在运行（`.\start_actions.ps1`），再训练并重启 API（`rasa train` + `.\start_rasa.ps1 -RunOnly`）。当前仓库已补充大量借还口语样本，并下调 `FallbackClassifier.threshold` 以减少短句误判。

### 12. 从总览消息里整行复制（如「《书名》— 架位（索书号）」）后被判为听不懂

**原因**：整行文本含序号、架位、索书号等噪声，早期实现会把整句当书名，导致检索失败并触发兜底。  
**处理**：`backend/actions/actions.py` 已增强书名归一化：支持从 `《...》` 提取题名，自动剔除序号、架位和索书号片段。更新后请 `**rasa train`** 并重启 Action + API；如仍异常，优先在前端 Console 检查请求是否到达 `5055` 与 `5005`。

**补充（结构化总览）**：当前「书籍总览」以 `**overview_catalog`** 宽气泡表格展示，按页向 Neo4j 查询；**已浏览过的页码会缓存在浏览器**，返回上一页不再请求后端、也不显示翻页加载层。内部翻页依赖 NLU 意图 `**book_overview_pager`**（由前端发送固定口令触发），新增或调整相关训练数据后务必 `**rasa train**`。

### 13. 单书介绍（「介绍一下《三体》」等）

**说明**：意图 `**book_introduce`** 由 `action_book_introduce` 聚合 Neo4j 馆藏与图谱事实，可选调用 **DeepSeek** 写导读（环境变量 `**BOOK_INTRO_DEEPSEEK`**，未设置时沿用 `READING_RECOMMEND_DEEPSEEK` 开关语义；无 Key 时回退为事实摘要）。  
**处理**：配置 `.env` 中 `DEEPSEEK_API_KEY` 后重启 Action；改 `nlu.yml` 后 `**rasa train`**。

**作者介绍（`introduce_author`，构成对齐 library-RAG-Rasa 参考仓库）**：「介绍一下刘慈欣」「李航是谁」等触发 `action_introduce_author`：`neo4j_connector.get_author_profile` 模糊匹配作者（忽略「·」）并取档案（`primary_field`、`bio`、馆藏著作、作者关系网络），`llm_server.generate_author_reply` 生成介绍（优先本地 Ollama（配置 `OLLAMA_URL` 时）→ DeepSeek → 结构化兜底），回复后清空 `author` 槽防跨轮污染。作者档案来自 `kg_module/raw_data/authors.csv`（`--reset` 导入时自动写入 `primary_field` 与 `bio`）。

### 14. 我已经改了 `actions.py`，但对话行为没变

**原因**：Action Server 不会热加载 Python 代码；只重启 Rasa API（5005）仍会调用旧 Action 进程。  
**处理**：每次改动 `backend/actions/*.py` 后，按顺序重启：

1. 终端 1：`.\start_actions.ps1`（重启 5055）
2. 终端 2：`.\start_rasa.ps1 -RunOnly -Port 5005`（重启 5005）

### 15. 推荐后说「借这本 / 借第2本」没有进入借书

**原因**：常见为模型未重新训练，或 Action/Rasa 仅重启了其中一个。  
**处理**：执行 `rasa train` 后，同时重启 Action 与 Rasa；并尽量使用标准表达（如 `借这本`、`借第2本`、`借第二本`）。

## 七、Docker 部署（可选）

在已安装 [Docker Compose](https://docs.docker.com/compose/) 的机器上，可在**仓库根目录**执行：

```powershell
copy .env.example .env
# 编辑 .env，至少填写 DEEPSEEK_API_KEY（不填则「数据类咨询」仍为固定话术）

docker compose -f deploy/docker-compose.yml up --build
```

若提示 **无法将「docker」识别为命令**，说明本机未安装 Docker 或未加入 PATH；可安装 [Docker Desktop for Windows](https://docs.docker.com/desktop/install/windows-install/) 后重开终端。日常联调不必强依赖 Docker，按上文 **「三、日常联调」** 用 Conda 起 Action + Rasa + Vue 即可。

- **Rasa**：`http://127.0.0.1:5005`（构建镜像时会执行 `rasa train`，首次较慢）
- **Action**：`http://127.0.0.1:5055`；与 Core 之间通过 `backend/endpoints.docker.yml` 使用服务名 `actions` 互联
- **Neo4j**：`bolt://127.0.0.1:7687`，浏览器 `http://127.0.0.1:7474`（默认与 compose 中 `NEO4J_PASSWORD` 一致，见 `.env.example`）。**连通性自检命令**见上文 **「三、日常联调」→「测试 Neo4j 是否连通」**。
- **前端 Webhook** 仍填：`http://127.0.0.1:5005/webhooks/rest/webhook`（或把 Vue 也容器化后改用对应主机名）

首次写入图数据（本机已 `pip install neo4j` 且 Neo4j 已启动）：脚本会自动读取**仓库根目录**或 `**backend/`** 下的 `.env`。

- **有密码**：在 `.env` 中设置 `NEO4J_PASSWORD=...`（与实例 `NEO4J_AUTH` 一致）。
- **无密码仅测试**：Neo4j 必须以关闭鉴权方式运行（例如 `docker run ... -e NEO4J_AUTH=none ...`），并在 `.env` 中增加 `**NEO4J_AUTH_NONE=1`**（不要设置 `NEO4J_PASSWORD`）。

```powershell
conda activate rasa310

# 首次或「清空 Neo4j 演示数据（含 LibraryBook、BorrowRecord）后全量重导 CSV，并重灌馆藏种子」：
```

## 九、REST 调试与辅助脚本

### `backend/run_rasa_client.py`

用于向本机 Rasa HTTP 接口发文本（默认与脚本内 `SERVER_URL` 相关）。使用前在脚本中把 `SERVER_URL` 改为与当前部署一致，例如：

```text
http://127.0.0.1:5005/model/parse
```

或 Webhook 地址（视脚本实现而定）。在 `backend` 目录执行：`python run_rasa_client.py`。

### `backend/run_rasa_server.py`

独立 Flask 服务：将用户文本转发到本地 `5005` 的 `/model/parse`，再按意图路由到其它端口。其意图集合可能与当前**图书馆**域不一致，仅作 NLU 分发演示；使用前确认下游服务已就绪。
